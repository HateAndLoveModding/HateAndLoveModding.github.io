Over the past few months I have been using AI as a coding tool. I wanted to discuss how I have used AI over the past few months and how I think software engineers should use it going forward.

## Claude at Qualcomm

This summer was the first time I got to use the paid version of any AI tool. Me and three other Mines students were working on a data analytics chatbot for Qualcomm and Qualcomm gave us access to Claude. I was using tools, frameworks, and services I had never heard of before to build something I had also never heard of before. Though I didn't start out using Claude. Our client encouraged us to use Claude but I didn't quite embrace it yet. Since I had no idea how to build a RAG, I first watched a tutorial online about building a RAG from scratch. It was a series that was recorded by a software engineer at LangChain. I used the first couple videos to create a very simple and barebones but working RAG and tested it. I cannot tell you how much joy and awe I was in when I saw the retrieval step work for the first time. I thought it was amazing! I then spent a good amount of time refactoring that code to something that I felt like I really understood. I then was able to ingest the databases into the RAG and see the whole process in action. Then I started using Claude as essentially a vibe coding tool. I using Claude to vibe code all of the tests for the RAG. I also used it to help me figure out how I should now improve the RAG now that I had something working. I felt like it was only kinda helpful with actually improve the algorithm. But I also had Claude generate better descriptions for the data and that definitely boosted the RAG similarity scores. I didn't continue watching the series about building a RAG from scratch. I started relying more on Claude for what I should do. But later I went back to the series and looked at some of the other methods that had been developed to help improve RAG systems. I wasn't sure which ones I wanted to implement so I didn't right away. Then later when I woke up at 4a.m. and thought about it more and decided I should try to implement HyDE because I didn't think it would be too hard to implement and it made sense to me why it might work. So I used Claude to help me implement that and I gave another noticeable bump to the similarity scores. Towards the end of Field Session I had Claude generate some more tests because I felt like 30 was not enough so I had it generate 30 more tests. Overall I felt like I abused Claude a little bit and I let it do some things that I did not want. I also left feeling like I didn't fully understand the code. I let Claude carry me a little bit instead of staying in control. 

## AI over the summer

I tried to use AI more responsiblity and use documentation. I used Cursor to help me plan building my own RAG. I told it all the features I wanted and had it plan the project structure and functions I should use. I then used that to build the RAG. I would try to use documentation of the libraries and functions to help me write the code instead of letting AI just do it all for me. If I still needed help I would try to ask Cursor very specific questions to help get me unstuck. But my mistake was not critiquing the plan that Cursor generated. The structure seemed to have unnessessary files because they had one or two very short functions for files that were 10 lines long and functions that didn't really add anything. That made the code harder to read because everything was in different files. I think it would have been much better to just have 3-5 files and combine functions unless they would actually be called multiple times. 

## Claude in Programming Languages

I am taking Programming Languages right now and we are learning OCaml. I want to understand OCaml so for our first lab we were coding various simple recursive functions. I used Claude as a guide to help me come to the right answer. I was using it more like a teaching assistant who doesn't give the you answer but asks you questions that guide you to figure out the right answer. I learned a lot because that was the first time I was using OCaml by myself. I was coding a function that return the nth element of a list. I coded the function but then I spent a bunch more time coding another function that would test my other function. That was the hardest part and it wasn't part of the assignment but I learned how to write more complex functions in that and it taught me things that I never would have learned otherwise. While it wasn't technically test driven development because I wrote the function before the test function, I did think about all the edge cases and wrote those down so I was able to use my test function with a generally complete set of test cases immediately. I was also able to use Claude to guide me to ensure that my set of test cases was complete. By the end, I felt like I understood everything and had a good set of test cases and I have complete confidence that my function was correct. 

## Claude in Coding with AI Agents

For our first project in my Coding with AI Agents class, we are building our own website and hosting it using GitHub Pages. I spent two hours defining all the features I wanted. I also pushed back on the plan that Claude created. I also had it ask me more questions to clarify any confusion before starting to code. That was very helpful because then I was able to set up an orchestrator agent to facilitate sub-agents that would code my website. I set it up before I left for work and when I came back from work it had a fully built website. Since I spent so long on planning, it didn't need to ask me any more questions and was able to just use the plan to build the website. After that I reviewed everything and had Claude fix a couple issues or things that I didn't like. I also made sure that the orchestrator spawned code review agents to review the code. This was the first time I had fully let agents build everything for me and I was very happy with the result. 

## How I plan to use AI in the future

I will use AI as a guide or teaching assistant for things that I should make sure I understand and will make me a better software engineer. For things that I will most likely not use again or is not fundamental, I will use AI agents with code reviewers and lots of planning time to make sure that the code quality is good. This may change in the future because AI is changing every day and it could look completely different 6 months from now. I want to learn more about the limitations of AI and how to increase the quality of AI output. I also want to see what fully embracing AI looks like, where I don't even review the code myself but I just provide frameworks for the AI to ensure quality output. I will not use AI to carry me. I will learn what I need to and I will either use AI as an expert developer or a senior software engineer.
